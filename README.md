# my-coffee-store

ที่เก็บเอกสารประกอบการพัฒนาโปรเจกต์ **my-coffee-store**

> **สถานะปัจจุบัน — ยังไม่เริ่มพัฒนา**
> ที่เก็บนี้ยังไม่มีโค้ดของระบบ มีเพียง *โครงเอกสาร* ใน `docs/` ซึ่งเตรียมไว้รองรับการทำงานเท่านั้น
> ทุกไฟล์ใน `docs/` ยังเป็น `index.md` ที่อธิบายว่าโฟลเดอร์นั้นใช้เก็บอะไร **ยังไม่มีข้อกำหนด แผนงาน งานย่อย แบบออกแบบ หรือผลทดสอบจริง**
> ขั้นตอนถัดไปคือกำหนดขอบเขตและความต้องการของระบบไว้ใน [`docs/01-requirements/01-spec/`](docs/01-requirements/01-spec/index.md) ก่อนเป็นอันดับแรก

## โครงสร้างเอกสาร

`docs/` คือ Obsidian vault ที่วางโครงตาม **ลำดับการไหลของงาน (pipeline)** โดยผลลัพธ์ของแต่ละขั้นจะส่งต่อให้ขั้นถัดไป

```
01-requirements  →  02-design  →  03-testing  →  04-retrospectives
```

| โฟลเดอร์ | ใช้เก็บ |
| --- | --- |
| [01-requirements](docs/01-requirements/index.md) | ความต้องการของโปรเจกต์ แบ่งเป็น `01-spec` (ข้อกำหนด) → `02-plan` (แผนงาน/roadmap) → `03-task` (งานย่อยที่ลงมือทำได้) |
| [02-design](docs/02-design/index.md) | การออกแบบ แบ่งเป็น `01-prototypes` (UI/UX, wireframe) และ `02-technical` (architecture, database, API) |
| [03-testing](docs/03-testing/index.md) | การทดสอบ แบ่งเป็น `01-test-plan` (test case) และ `02-test-result` (ผลทดสอบและบั๊กที่พบ) |
| [04-retrospectives](docs/04-retrospectives/index.md) | สรุปบทเรียนหลังจบแต่ละ phase หรือ milestone |
| [05-log](docs/05-log/index.md) | บันทึกความเคลื่อนไหวตามลำดับเวลา — changelog และบันทึกการตัดสินใจพร้อมเหตุผล |
| [00-archived](docs/00-archived/index.md) | เอกสารที่เลิกใช้แล้ว เก็บไว้เพื่ออ้างอิงย้อนหลัง |

ตัวเลขนำหน้าชื่อโฟลเดอร์ (`01-`, `02-`, …) สื่อถึง **ลำดับในกระบวนการ** ไม่ใช่การตั้งชื่อตามใจ ส่วน `00-` สงวนไว้สำหรับเอกสารที่เก็บเข้าคลัง

## วิธีใช้งาน

เปิดโฟลเดอร์นี้เป็น vault ใน [Obsidian](https://obsidian.md) เพื่อให้ลิงก์ระหว่างเอกสารและมุมมอง graph ทำงานได้ครบ หรือจะอ่านเป็นไฟล์ Markdown ธรรมดาก็ได้เช่นกัน

ก่อนเพิ่มเอกสารลงในโฟลเดอร์ใด ให้อ่าน `index.md` ของโฟลเดอร์นั้นก่อน เพราะแต่ละไฟล์ระบุไว้ชัดเจนว่ารับข้อมูลมาจากที่ใดและส่งผลลัพธ์ต่อไปที่ใด

## ข้อตกลงในการเขียนเอกสาร

- **เขียนเป็นภาษาไทย** ให้สอดคล้องกับเอกสารเดิมทั้งหมด
- **ทุกโฟลเดอร์ต้องมี `index.md`** ทำหน้าที่เป็นหน้าแรกและคำอธิบายของโฟลเดอร์นั้น
- **ลิงก์ภายใน `docs/` ใช้ wikilink พร้อมป้ายกำกับ** และชี้ไปที่ `index` เสมอ เช่น `[[../02-plan/index|02-plan]]`
  (ยกเว้นไฟล์ README นี้ที่ใช้ลิงก์ Markdown ปกติ เพื่อให้กดได้บนหน้าเว็บ GitHub)
- **ห้ามลบเอกสารทิ้ง** หากเลิกใช้แล้วให้ย้ายไปไว้ที่ `docs/00-archived/` เพื่อรักษาประวัติการตัดสินใจ
- **บันทึกการตัดสินใจสำคัญไว้ใน `docs/05-log/`** พร้อมเหตุผล เพื่อให้ย้อนกลับมาทบทวนได้ว่าทำไมจึงเลือกทางนั้น
