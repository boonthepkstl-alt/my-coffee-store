## ช่องว่างที่พบระหว่างเขียน (ไม่สร้าง test case ทับ เพราะไม่มี AC รองรับ)

- **กฎ validation ของราคาเมนู** (เช่น ห้ามติดลบ, ทศนิยมกี่ตำแหน่ง) — ไม่มี AC หรือ
  business rule ใดระบุไว้ในสเปค ต้องส่งต่อ `acceptance-criteria-writer` เพื่อถามคน
  ก่อน ไม่ใช่สมมติกฎเอง (ตรงกับพฤติกรรมที่ระบุไว้ใน `test-writer` — "มีช่องว่าง AC")
- **AC-2 ("เมื่อเปิดหน้าเมนู ต้องแสดงเฉพาะรายการที่เปิดขายอยู่")** — ข้อความไม่ระบุ
  ชัดว่าหมายถึงหน้าเมนูฝั่งลูกค้า (BL-003) หรือหน้ารายการเมนูฝั่งพนักงาน (BL-001)
  งานนี้ตีความว่าหมายถึงฝั่งลูกค้า จึง**ไม่**สร้าง test case ผูกกับ AC-2 ในเอกสารนี้
  — ควรยืนยันก่อนเขียน test case ของ BL-003
- **Loading state ระหว่างบันทึก** — ไม่มี AC ระบุพฤติกรรมนี้ตรง ๆ (เป็นเพียง state
  ที่ prototype ต้องพิจารณาตาม AI Design Rule 8 ไม่ใช่ acceptance criteria)
