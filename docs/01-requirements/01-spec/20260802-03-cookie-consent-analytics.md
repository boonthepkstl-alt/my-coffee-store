# ความยินยอมสำหรับคุกกี้และการวิเคราะห์การใช้งาน

> ⚠️ **เอกสารนี้ไม่ใช่คำแนะนำทางกฎหมาย**
> เขียนโดยผู้ที่ไม่ใช่นักกฎหมาย เพื่อใช้เป็นจุดตั้งต้นในการคุยกับที่ปรึกษากฎหมายเท่านั้น
> การอ้างอิงมาตราและกรอบเวลาต้องได้รับการยืนยันอีกครั้ง — ดู [[20260802-02-pdpa-it-compliance|20260802-02]]

## 1. ที่มาและปัญหา

เอกสาร [[20260802-02-pdpa-it-compliance|20260802-02]] วางข้อกำหนด PDPA ในภาพรวมไว้แล้ว
แต่ครอบคลุมเฉพาะข้อมูลที่ลูกค้า **ตั้งใจส่งให้** ตอนสั่งสินค้า ยังไม่ครอบคลุมข้อมูลที่ระบบ
**เก็บโดยลูกค้าไม่รู้ตัว** ซึ่งได้แก่คุกกี้ IP address และข้อมูลพฤติกรรมที่ส่งไปยัง Google Analytics

ประเด็นที่ทำให้ต้องแยกเป็นเอกสารเฉพาะ:

1. **Google Analytics ส่งข้อมูลออกไปต่างประเทศ** — ข้อมูลถูกส่งไปยังเซิร์ฟเวอร์ของ Google
   ซึ่งอยู่นอกประเทศไทย เอกสาร `20260802-02` ระบุ "การโอนข้อมูลส่วนบุคคลไปต่างประเทศ"
   ไว้ใน **out of scope** ดังนั้นการใส่ GA เข้ามาจึงขัดกับขอบเขตเดิม และต้องจัดการอย่างชัดเจน
2. **IP address อยู่ภายใต้ฐานทางกฎหมายสองฐานพร้อมกัน** — ฐานเดียวกันใช้อธิบายทั้งสองกรณีไม่ได้
   หากออกแบบรวมกันจะเกิดข้อผิดพลาดที่ยากตรวจพบ
3. คุกกี้และ analytics ส่งมอบแยกจากระบบสั่งอาหารได้ ระบบสั่งอาหารใช้งานได้โดยไม่มี GA

> **คำขอเดิมจากผู้ใช้:**
> "เพิ่มเติมในส่วนของข้อกฎหมาย IT ในการเก็บ Log เป็นระยะเวลา 90 วัน และ PDPA สำหรับให้ผู้ใช้งาน
> ที่เป็นผู้ซื้อทราบ ในเรื่องของการเก็บ Consent ที่จะมีการใช้งาน Google Analytic และ IP Address
> หรืออื่นๆ ที่เกี่ยวข้อง แนะนำเพิ่มเติม หรือไม่แน่ใจให้ถาม"

### ฐานทางกฎหมายของ IP address — แยกตามวัตถุประสงค์

นี่คือหัวใจของเอกสารนี้ ผู้พัฒนาต้องเข้าใจตารางนี้ก่อนเขียนโค้ด

| วัตถุประสงค์ | ฐานทางกฎหมาย | ขอความยินยอม? | ถอนได้? | รูปแบบที่เก็บ |
| --- | --- | --- | --- | --- |
| ข้อมูลจราจรตาม พ.ร.บ. คอมพิวเตอร์ | หน้าที่ตามกฎหมาย | **ไม่ต้องขอ** | **ถอนไม่ได้** | IP เต็ม |
| การวิเคราะห์การใช้งาน (GA4) | ความยินยอม | **ต้องขอก่อนเก็บ** | **ถอนได้ตลอดเวลา** | IP ตัดทอน |
| ป้องกันการโจมตี / rate limiting | ประโยชน์อันชอบด้วยกฎหมาย | ไม่ต้องขอ | คัดค้านได้ | IP เต็ม ชั่วคราว |

**ข้อผิดพลาดที่ต้องระวัง:** เมื่อลูกค้าปฏิเสธคุกกี้วิเคราะห์ ระบบต้อง **ยังเก็บ log ตามกฎหมายต่อไป**
การหยุดเก็บ log เพราะลูกค้าปฏิเสธคุกกี้ คือการทำผิด พ.ร.บ. คอมพิวเตอร์ และในทางกลับกัน
การอ้าง log ตามกฎหมายเพื่อยิง GA โดยไม่ขอความยินยอม คือการทำผิด PDPA

## 2. ขอบเขต

### สิ่งที่ทำ (In scope)

- Cookie consent banner แบบแยกหมวดหมู่ ให้ลูกค้าเลือกรายประเภทได้
- หมวดคุกกี้ 3 หมวด — จำเป็น (เปิดตลอด ปิดไม่ได้) / วิเคราะห์ / การตลาด
- ติดตั้ง Google Analytics 4 พร้อม Consent Mode โดยบล็อกการยิงข้อมูลจนได้รับความยินยอม
- ตัดทอน IP address ในส่วนของ analytics
- เก็บ IP address แบบเต็มในข้อมูลจราจรตามกฎหมาย โดยไม่ผูกกับความยินยอม
- นโยบายคุกกี้ (Cookie Policy) แยกจากนโยบายความเป็นส่วนตัว
- หน้าจัดการความยินยอม ให้ลูกค้ากลับมาแก้ไขหรือถอนได้ภายหลัง
- บันทึกหลักฐานความยินยอม — เวลา เวอร์ชันนโยบาย และหมวดที่เลือก
- ประเมินและจัดทำเอกสารการโอนข้อมูลส่วนบุคคลไปต่างประเทศสำหรับ Google

### สิ่งที่ไม่ทำ (Out of scope)

- คุกกี้เพื่อการตลาดและโฆษณา — เตรียมหมวดไว้ใน banner แต่ยังไม่มีการใช้งานจริงในเฟสนี้
- Google Ads, Facebook Pixel และเครื่องมือติดตามอื่นนอกจาก GA4
- การทำ A/B testing และการเก็บ session recording หรือ heatmap
- การวิเคราะห์ข้อมูลระดับบุคคล (user-level tracking) — เฟสนี้ดูภาพรวมเท่านั้น
- ข้อกำหนดคุกกี้ตามกฎหมายต่างประเทศ เช่น ePrivacy Directive
- การขยายระยะเวลาเก็บ log เกิน 90 วันตามคำสั่งพนักงานเจ้าหน้าที่ — ดู Q4

## 3. ผู้ใช้ที่เกี่ยวข้อง

| กลุ่มผู้ใช้ | สิ่งที่ต้องการจากระบบ |
| --- | --- |
| ลูกค้า (ผู้ซื้อ) | รู้ว่าถูกเก็บข้อมูลอะไรก่อนที่จะถูกเก็บ และเลือกปฏิเสธได้จริงโดยยังใช้งานระบบได้ |
| เจ้าของร้าน | มีข้อมูลสถิติพอใช้ตัดสินใจ โดยไม่สร้างความเสี่ยงทางกฎหมาย |
| ผู้พัฒนาระบบ | รู้ชัดว่าอะไรยิงได้ก่อนยินยอม อะไรต้องรอ และ IP ต้องเก็บรูปแบบใดในแต่ละที่ |
| ผู้ดูแลระบบ | เก็บ log ครบตามกฎหมาย และค้นย้อนหลังได้เมื่อถูกขอ |
| ที่ปรึกษากฎหมาย | เห็นการไหลของข้อมูลออกนอกประเทศทั้งหมด เพื่อประเมินความเสี่ยง |

## 4. User stories

- **US-1** — ในฐานะผู้ซื้อ ฉันต้องการรู้ก่อนว่าเว็บจะเก็บข้อมูลการใช้งานของฉัน เพื่อเลือกได้ว่าจะยอมหรือไม่
- **US-2** — ในฐานะผู้ซื้อ ฉันต้องการปฏิเสธคุกกี้วิเคราะห์แล้วยังสั่งกาแฟได้ปกติ เพราะการปฏิเสธไม่ควรทำให้ใช้บริการไม่ได้
- **US-3** — ในฐานะผู้ซื้อ ฉันต้องการเลือกยอมรับเฉพาะบางหมวด ไม่ใช่ต้องยอมทั้งหมดหรือไม่ยอมเลย
- **US-4** — ในฐานะผู้ซื้อ ฉันต้องการกลับมาเปลี่ยนใจและถอนความยินยอมได้ภายหลัง
- **US-5** — ในฐานะผู้ซื้อ ฉันต้องการรู้ว่าข้อมูลของฉันถูกส่งไปต่างประเทศหรือไม่ เพื่อประเมินความเสี่ยงเอง
- **US-6** — ในฐานะเจ้าของร้าน ฉันต้องการดูสถิติผู้เข้าชม เพื่อรู้ว่าช่วงเวลาไหนคนใช้งานเยอะ
- **US-7** — ในฐานะผู้ดูแลระบบ ฉันต้องการค้นข้อมูลจราจรย้อนหลัง 90 วันได้ แม้ลูกค้าจะปฏิเสธคุกกี้

## 5. กฎทางธุรกิจ (Business rules)

- **BR-1** — ห้ามยิง tag ของ Google Analytics หรือวางคุกกี้ที่ไม่จำเป็นก่อนได้รับความยินยอมโดยเด็ดขาด
- **BR-2** — คุกกี้หมวด "จำเป็น" เปิดตลอดและปิดไม่ได้ ต้องจำกัดเฉพาะที่ระบบทำงานไม่ได้หากขาดไปจริง
- **BR-3** — ค่าเริ่มต้นของหมวด "วิเคราะห์" และ "การตลาด" ต้องเป็น **ไม่ยินยอม** ห้ามติ๊กมาให้ล่วงหน้า
- **BR-4** — ปุ่มปฏิเสธต้องเห็นชัดและกดได้ง่ายไม่น้อยกว่าปุ่มยอมรับ ห้ามออกแบบให้ปฏิเสธยากกว่ายอมรับ
- **BR-5** — การปฏิเสธคุกกี้ต้องไม่ทำให้ลูกค้าสั่งสินค้าไม่ได้
- **BR-6** — IP address ในข้อมูลจราจรตามกฎหมายต้องเก็บแบบเต็ม และ **ไม่ผูกกับความยินยอม**
- **BR-7** — IP address ที่ส่งเข้า analytics ต้องถูกตัดทอนก่อนส่งออกจากระบบเสมอ
- **BR-8** — เมื่อลูกค้าถอนความยินยอม ต้องหยุดเก็บข้อมูลวิเคราะห์ทันที และลบคุกกี้ที่เกี่ยวข้องออกจากเบราว์เซอร์
- **BR-9** — การถอนความยินยอมต้องไม่กระทบการเก็บ log ตามกฎหมาย
- **BR-10** — ทุกครั้งที่บันทึกความยินยอม ต้องเก็บเวลา เวอร์ชันนโยบาย และหมวดที่เลือกไว้เป็นหลักฐาน
- **BR-11** — เมื่อนโยบายคุกกี้เปลี่ยน ต้องขอความยินยอมใหม่ ห้ามถือว่าความยินยอมเดิมครอบคลุม
- **BR-12** — ต้องแจ้งลูกค้าอย่างชัดเจนว่าข้อมูลถูกส่งไปยังผู้ให้บริการต่างประเทศรายใด และเพื่ออะไร
- **BR-13** — ต้องมีสัญญาการประมวลผลข้อมูล (DPA) กับ Google ก่อนเริ่มใช้งานจริง

## 6. เกณฑ์การยอมรับ (Acceptance criteria)

- [ ] **AC-1** — เมื่อเปิดเว็บครั้งแรก ต้องเห็น consent banner ก่อนใช้งาน และแยกหมวดให้เลือกได้ 3 หมวด
- [ ] **AC-2** — เมื่อเปิดเว็บครั้งแรกและยังไม่กดอะไร ตรวจ network request ต้องไม่พบการเรียกไปยังโดเมนของ Google
- [ ] **AC-3** — เมื่อเปิดเว็บครั้งแรกและยังไม่กดอะไร ตรวจ cookie storage ต้องพบเฉพาะคุกกี้หมวดจำเป็น
- [ ] **AC-4** — เมื่อเปิด banner ครั้งแรก หมวดวิเคราะห์และการตลาดต้องอยู่ในสถานะปิด
- [ ] **AC-5** — เมื่อกดปฏิเสธทั้งหมด ต้องยังสั่งสินค้าได้จนจบขั้นตอนโดยไม่มีอุปสรรค
- [ ] **AC-6** — เมื่อกดยอมรับหมวดวิเคราะห์ GA4 ต้องเริ่มส่งข้อมูลได้ภายใน 5 วินาทีโดยไม่ต้องรีเฟรช
- [ ] **AC-7** — เมื่อยอมรับเฉพาะหมวดวิเคราะห์ ต้องไม่มีคุกกี้หมวดการตลาดถูกวาง
- [ ] **AC-8** — เมื่อตรวจข้อมูลที่ส่งเข้า GA4 ต้องไม่พบ IP address แบบเต็ม
- [ ] **AC-9** — เมื่อตรวจ log ตามกฎหมายของลูกค้าที่ปฏิเสธคุกกี้ ต้องยังพบ IP address แบบเต็มครบถ้วน
- [ ] **AC-10** — เมื่อถอนความยินยอม คุกกี้วิเคราะห์ต้องถูกลบออกจากเบราว์เซอร์ และ GA ต้องหยุดส่งข้อมูล
- [ ] **AC-11** — เมื่อถอนความยินยอมแล้วตรวจ log ตามกฎหมาย ต้องยังบันทึกต่อเนื่องไม่ขาดช่วง
- [ ] **AC-12** — เมื่อเปิดหน้าจัดการความยินยอม ต้องเห็นสถานะที่เลือกไว้ล่าสุดตรงตามที่บันทึก
- [ ] **AC-13** — เมื่อค้นฐานข้อมูลความยินยอม ต้องพบเวลา เวอร์ชันนโยบาย และหมวดที่เลือกของทุกรายการ
- [ ] **AC-14** — เมื่ออัปเดตเวอร์ชันนโยบายคุกกี้ ลูกค้าเดิมต้องเห็น banner ขอความยินยอมใหม่
- [ ] **AC-15** — เมื่อเปิดนโยบายคุกกี้ ต้องพบรายชื่อคุกกี้ทุกตัวที่ระบบใช้จริง พร้อมวัตถุประสงค์และอายุ
- [ ] **AC-16** — เมื่อเปิดนโยบายความเป็นส่วนตัว ต้องพบข้อความระบุว่ามีการส่งข้อมูลไปยัง Google ในต่างประเทศ

## 7. กรณีข้อผิดพลาดและกรณีขอบ

| กรณี | พฤติกรรมที่คาดหวัง |
| --- | --- |
| ลูกค้าปฏิเสธคุกกี้วิเคราะห์ | หยุดยิง GA แต่ **ยังเก็บ log ตามกฎหมายต่อไป** — สองเรื่องนี้แยกกันเด็ดขาด |
| ลูกค้าปิด banner ด้วยปุ่ม X หรือกดพื้นที่ว่าง | ถือว่า **ไม่ยินยอม** ห้ามตีความว่ายินยอม |
| ลูกค้าใช้เบราว์เซอร์ที่บล็อกคุกกี้ทั้งหมด | ระบบต้องยังสั่งสินค้าได้ และไม่ค้างรอ consent ที่บันทึกไม่ได้ |
| ลูกค้าล้างคุกกี้แล้วกลับมา | ถือว่ายังไม่เคยยินยอม ต้องแสดง banner ใหม่ |
| ลูกค้าสแกน QR จากมือถือเครื่องใหม่ | ความยินยอมผูกกับเบราว์เซอร์ จึงต้องขอใหม่ในเครื่องใหม่ |
| GA โหลดไม่สำเร็จหรือถูกบล็อก | ระบบหลักต้องทำงานต่อได้ ห้ามให้ปัญหา analytics ทำให้สั่งของไม่ได้ |
| ลูกค้าขอดูข้อมูลที่ GA เก็บไว้ | ต้องอธิบายได้ว่าเก็บอะไร และชี้ช่องทางของ Google — เพราะร้านเข้าถึงข้อมูลระดับบุคคลไม่ได้ |
| ลูกค้าขอลบข้อมูลใน GA | ต้องมีขั้นตอนที่ทำได้จริง หรือแจ้งข้อจำกัดอย่างตรงไปตรงมา ห้ามรับปากลอย ๆ |
| log เต็มพื้นที่จัดเก็บก่อนครบ 90 วัน | ต้องแจ้งเตือนผู้ดูแลก่อนถึงจุดวิกฤต ห้ามลบ log ทิ้งเงียบ ๆ |
| ลูกค้าปฏิเสธ แต่เจ้าของร้านอยากได้ตัวเลขครบ | ตัวเลขจะต่ำกว่าความจริงตามที่ยอมรับไว้ใน Q1 ห้ามแก้ด้วยการยิง GA ก่อนยินยอม |

## 8. คำถามที่ยังค้าง

รายการนี้ต้องว่างก่อนเปลี่ยน `status` เป็น `ใช้งาน`

**คำถามที่ได้คำตอบแล้วในรอบนี้** — บันทึกไว้เพื่อให้ย้อนดูได้ว่าตัดสินใจอะไรไป

- ✅ **ใช้ GA4 พร้อม Consent Mode** บล็อกการยิงข้อมูลจนได้รับความยินยอม
  ยอมรับว่าตัวเลขสถิติจะต่ำกว่าความเป็นจริง เพราะไม่นับผู้ที่ปฏิเสธ
- ✅ **Consent banner แบบแยกหมวดหมู่** 3 หมวด — จำเป็น / วิเคราะห์ / การตลาด
- ✅ **IP address แยกตามวัตถุประสงค์** — log ตามกฎหมายเก็บเต็ม analytics ตัดทอน
- ✅ **ข้อมูลจราจร 90 วัน ประกอบด้วย** IP + เวลา + URL + user agent + บัญชีผู้ใช้

**คำถามที่ยังไม่ได้คำตอบ**

- [ ] **Q1 — ตัดทอน IP ด้วยวิธีใด?** ตัด octet สุดท้าย หรือ hash พร้อม salt ที่หมุนเวียน
      กระทบ BR-7 และ AC-8 — ต้องให้ที่ปรึกษากฎหมายยืนยันว่าวิธีที่เลือกถือว่าไม่ระบุตัวตนได้จริง
- [ ] **Q2 — เก็บบันทึกความยินยอมนานเท่าไร?** ต่างจากระยะเวลาเก็บข้อมูลออร์เดอร์
      โดยหลักควรเก็บนานกว่า เพื่อพิสูจน์ได้ว่าเคยได้รับความยินยอมเมื่อใด
- [ ] **Q3 — คุกกี้ใดจัดเป็น "จำเป็น" ได้บ้าง?** ต้องระบุรายตัวก่อนพัฒนา
      เพราะการจัดคุกกี้ที่ไม่จำเป็นเข้าหมวดนี้เพื่อเลี่ยงการขอความยินยอม คือการทำผิด PDPA
- [ ] **Q4 — เตรียมรับคำสั่งขยายเวลาเก็บ log เกิน 90 วันหรือไม่?** กฎหมายเปิดให้เจ้าหน้าที่สั่งขยายได้
      หากไม่ออกแบบรองรับไว้ จะขยายไม่ได้ทันเมื่อถูกสั่ง
- [ ] **Q5 — ใครเป็นผู้ลงนามใน DPA กับ Google?** ต้องเป็นผู้มีอำนาจของกิจการ ไม่ใช่ทีมพัฒนา
- [ ] **Q6 — ที่ปรึกษากฎหมายตรวจเอกสารนี้แล้วหรือยัง?** ยังไม่ได้ตรวจ
      **ห้ามเปลี่ยนสถานะเป็น `ใช้งาน` ก่อนข้อนี้ผ่าน** โดยเฉพาะประเด็นการโอนข้อมูลไปต่างประเทศ
