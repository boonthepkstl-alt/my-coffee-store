# ระบบรับออร์เดอร์ด้วยตนเองจากโต๊ะ

> ⚠️ **เอกสารนี้ยังเป็นร่าง** — ข้อ 4 ประเด็นหลักในหัวข้อ [8. คำถามที่ยังค้าง](#8-คำถามที่ยังค้าง)
> ยังไม่ได้รับคำตอบจากผู้ใช้ เนื้อหาด้านล่างเขียนบน **สมมติฐานชั่วคราว** ที่ทำเครื่องหมาย
> `[สมมติฐาน]` ไว้ หากคำตอบจริงต่างออกไป ขอบเขตและรายการ backlog จะเปลี่ยนตามอย่างมีนัยสำคัญ
> ห้ามนำไปเริ่มพัฒนาก่อนยืนยันคำตอบ

## 1. ที่มาและปัญหา

ร้านกาแฟรับออร์เดอร์ผ่านพนักงานที่เคาน์เตอร์เพียงช่องทางเดียว ทำให้เกิดคอขวดในช่วงเวลาเร่งด่วน
ลูกค้าต้องลุกจากโต๊ะและต่อคิวเพื่อสั่ง ส่วนพนักงานต้องสลับไปมาระหว่างการรับออร์เดอร์กับการชงเครื่องดื่ม
ทั้งสองฝ่ายเสียเวลาโดยไม่จำเป็น

ระบบนี้ย้ายขั้นตอนการสั่งไปอยู่ในมือลูกค้าที่โต๊ะ เพื่อลดคิวหน้าเคาน์เตอร์
และให้พนักงานโฟกัสกับการผลิตเครื่องดื่มได้เต็มที่

> **คำขอเดิมจากผู้ใช้:**
> "อยากสร้างระบบร้านกาแฟ ต้องการสร้างระบบรับ Order จากลูกค้า โดยลูกค้าสามารถ Order ได้เองจากโต๊ะ
> ถ้ามีอะไรไม่แน่ใจให้แนะนำ และถามก่อน"

## 2. ขอบเขต

### สิ่งที่ทำ (In scope)

- ลูกค้าสแกน QR code ประจำโต๊ะ แล้วเปิดหน้าสั่งอาหารบนมือถือของตนเอง `[สมมติฐาน — ดู Q1]`
- ดูเมนูพร้อมรูป ราคา และตัวเลือก (ขนาด ร้อน/เย็น/ปั่น ระดับความหวาน ท็อปปิ้ง)
- เพิ่มลงตะกร้า แก้ไขจำนวน และระบุหมายเหตุถึงบาริสต้า
- ชำระเงินออนไลน์ทันทีที่ยืนยันการสั่ง `[สมมติฐาน — ดู Q2]`
- ออร์เดอร์ที่ชำระเงินแล้วปรากฏบนหน้าจอบาริสต้าพร้อมหมายเลขโต๊ะ `[สมมติฐาน — ดู Q3]`
- บาริสต้าอัปเดตสถานะออร์เดอร์เป็น "รับแล้ว" และ "เสร็จแล้ว"
- พนักงานเปิด/ปิดการขายรายเมนูได้เอง เมื่อของหมด `[สมมติฐาน — ดู Q4]`
- ระบบผู้ใช้สำหรับพนักงานร้าน แยกสิทธิ์เจ้าของร้านกับพนักงานทั่วไป

### สิ่งที่ไม่ทำ (Out of scope)

- สั่งกลับบ้าน สั่งล่วงหน้า และเดลิเวอรี่ — เฟสนี้รองรับเฉพาะลูกค้าที่นั่งในร้าน
- ระบบสมาชิก สะสมแต้ม และคูปองส่วนลด
- ตัดสต๊อกวัตถุดิบอัตโนมัติ และระบบสูตรเครื่องดื่ม
- รายงานยอดขายและวิเคราะห์ข้อมูลเชิงลึก
- ระบบ POS สำหรับพนักงานรับออร์เดอร์แทนลูกค้าที่เคาน์เตอร์
- แยกบิลหรือหารบิลระหว่างลูกค้าในโต๊ะเดียวกัน
- แอปมือถือที่ต้องติดตั้ง (iOS / Android)

## 3. ผู้ใช้ที่เกี่ยวข้อง

| กลุ่มผู้ใช้ | สิ่งที่ต้องการจากระบบ |
| --- | --- |
| ลูกค้าที่นั่งในร้าน | สั่งเครื่องดื่มจากโต๊ะได้เองโดยไม่ต้องต่อคิว รู้ว่าออร์เดอร์ถึงร้านแล้ว |
| บาริสต้า | เห็นออร์เดอร์ใหม่ทันที รู้ว่าโต๊ะไหนสั่งอะไร และกดปิดงานเมื่อทำเสร็จ |
| พนักงานหน้าร้าน | ปิดเมนูที่ของหมดได้ทันที ตรวจสอบสถานะออร์เดอร์แต่ละโต๊ะได้ |
| เจ้าของร้าน | จัดการเมนูและราคา จัดการบัญชีพนักงาน |

## 4. User stories

- **US-1** — ในฐานะลูกค้า ฉันต้องการสแกน QR ที่โต๊ะแล้วเห็นเมนูทันที เพื่อสั่งได้โดยไม่ต้องลุกไปเข้าคิว
- **US-2** — ในฐานะลูกค้า ฉันต้องการเลือกตัวเลือกของเครื่องดื่ม เพื่อให้ได้แบบที่ต้องการโดยไม่ต้องอธิบายด้วยปาก
- **US-3** — ในฐานะลูกค้า ฉันต้องการเห็นยอดรวมก่อนยืนยัน เพื่อตรวจสอบก่อนจ่ายเงิน
- **US-4** — ในฐานะลูกค้า ฉันต้องการรู้ว่าออร์เดอร์ส่งถึงร้านแล้ว เพื่อไม่ต้องเดินไปถามที่เคาน์เตอร์
- **US-5** — ในฐานะบาริสต้า ฉันต้องการเห็นออร์เดอร์ใหม่พร้อมหมายเลขโต๊ะบนหน้าจอเดียว เพื่อทำงานตามลำดับได้
- **US-6** — ในฐานะพนักงาน ฉันต้องการปิดเมนูที่ของหมดได้เอง เพื่อไม่ให้ลูกค้าสั่งของที่ทำไม่ได้
- **US-7** — ในฐานะเจ้าของร้าน ฉันต้องการแก้ไขเมนูและราคาได้เอง เพื่อไม่ต้องรอผู้พัฒนา

## 5. กฎทางธุรกิจ (Business rules)

- **BR-1** — ออร์เดอร์ทุกใบต้องผูกกับหมายเลขโต๊ะเสมอ ไม่มีออร์เดอร์ที่ไม่ระบุโต๊ะ
- **BR-2** — ออร์เดอร์จะปรากฏบนหน้าจอบาริสต้าเมื่อชำระเงินสำเร็จแล้วเท่านั้น `[สมมติฐาน — ดู Q2]`
- **BR-3** — เมนูที่ถูกปิดการขายต้องไม่แสดงให้ลูกค้าเลือก และต้องปฏิเสธหากถูกส่งเข้ามา
- **BR-4** — ราคาที่ใช้คิดเงินคือราคา ณ เวลาที่ยืนยันออร์เดอร์ การแก้ราคาภายหลังไม่กระทบออร์เดอร์เดิม
- **BR-5** — ลูกค้ายกเลิกออร์เดอร์เองไม่ได้หลังชำระเงิน ต้องให้พนักงานเป็นผู้ดำเนินการ
- **BR-6** — หนึ่งโต๊ะสั่งได้หลายออร์เดอร์ แต่ละใบแยกกันและแยกชำระเงิน
- **BR-7** — เฉพาะบัญชีระดับเจ้าของร้านเท่านั้นที่แก้ไขเมนูและราคาได้

## 6. เกณฑ์การยอมรับ (Acceptance criteria)

- [ ] **AC-1** — เมื่อสแกน QR ของโต๊ะใด ระบบต้องแสดงหมายเลขโต๊ะนั้นบนหน้าจอ และผูกออร์เดอร์กับโต๊ะนั้นโดยลูกค้าไม่ต้องกรอกเอง
- [ ] **AC-2** — เมื่อเปิดหน้าเมนู ต้องแสดงเฉพาะรายการที่เปิดขายอยู่ รายการที่ปิดขายต้องไม่ปรากฏ
- [ ] **AC-3** — เมื่อเลือกตัวเลือกที่มีค่าใช้จ่ายเพิ่ม ยอดรวมในตะกร้าต้องอัปเดตให้ตรงทันที
- [ ] **AC-4** — เมื่อชำระเงินสำเร็จ ออร์เดอร์ต้องปรากฏบนหน้าจอบาริสต้าภายใน 5 วินาที
- [ ] **AC-5** — เมื่อชำระเงินไม่สำเร็จ ต้องไม่มีออร์เดอร์เกิดขึ้น และตะกร้าของลูกค้าต้องยังอยู่ครบ
- [ ] **AC-6** — เมื่อบาริสต้ากด "เสร็จแล้ว" สถานะออร์เดอร์ต้องเปลี่ยน และออกจากคิวที่รอทำ
- [ ] **AC-7** — เมื่อพนักงานปิดการขายเมนูใด ลูกค้าที่เปิดหน้าเมนูอยู่ต้องสั่งรายการนั้นไม่สำเร็จ
- [ ] **AC-8** — เมื่อผู้ใช้ที่ไม่ใช่เจ้าของร้านพยายามแก้ไขราคา ระบบต้องปฏิเสธ

## 7. กรณีข้อผิดพลาดและกรณีขอบ

| กรณี | พฤติกรรมที่คาดหวัง |
| --- | --- |
| ลูกค้ากดยืนยันซ้ำหลายครั้ง | สร้างออร์เดอร์ใบเดียว ไม่ตัดเงินซ้ำ |
| ชำระเงินสำเร็จแต่ระบบล่มก่อนบันทึกออร์เดอร์ | ต้องกู้คืนออร์เดอร์ได้ หรือแจ้งพนักงานให้ตรวจสอบ ห้ามเงียบ |
| เมนูถูกปิดขายระหว่างที่ลูกค้ากำลังเลือก | แจ้งเตือนตอนยืนยัน และให้ลูกค้าเอารายการนั้นออกก่อนจ่ายเงิน |
| มือถือลูกค้าไม่มีอินเทอร์เน็ต | แสดงข้อความชัดเจน และแนะนำให้สั่งที่เคาน์เตอร์แทน |
| ลูกค้าสแกน QR ของโต๊ะอื่น | ระบบเชื่อตาม QR ที่สแกน — พนักงานต้องแก้ไขโต๊ะให้ได้ภายหลัง |
| ลูกค้าย้ายโต๊ะหลังสั่งแล้ว | พนักงานต้องเปลี่ยนหมายเลขโต๊ะของออร์เดอร์ได้ |
| หน้าจอบาริสต้าหลุดการเชื่อมต่อ | เมื่อกลับมาต้องดึงออร์เดอร์ที่ค้างมาแสดงครบ ไม่มีใบตกหล่น |
| ลูกค้าปิดเบราว์เซอร์หลังจ่ายเงิน | ออร์เดอร์ยังเดินหน้าตามปกติ ไม่ผูกกับการเปิดหน้าเว็บค้างไว้ |

## 8. คำถามที่ยังค้าง

รายการนี้ต้องว่างก่อนเปลี่ยน `status` เป็น `ใช้งาน`

- [ ] **Q1 — ลูกค้าสั่งผ่านช่องทางไหน?** ปัจจุบันสมมติว่าเป็น QR code + เว็บบนมือถือลูกค้า
      ทางเลือกอื่นคือแท็บเล็ตติดโต๊ะ แอปที่ต้องติดตั้ง หรือคีออสก์กลางร้าน
      **ผลกระทบ:** เปลี่ยนสถาปัตยกรรมทั้งหมด และเปลี่ยนต้นทุนฮาร์ดแวร์ต่อโต๊ะ
- [ ] **Q2 — ลูกค้าจ่ายเงินตอนไหน?** ปัจจุบันสมมติว่าจ่ายทันทีตอนสั่งผ่านออนไลน์
      ทางเลือกอื่นคือจ่ายที่เคาน์เตอร์หลังสั่ง หรือเปิดบิลไว้แล้วจ่ายตอนกลับ
      **ผลกระทบ:** กระทบ BR-2, AC-4, AC-5 และ BL-004 ทั้งหมด หากเลือกเปิดบิลจะต้องเพิ่มระบบผูกบิลกับโต๊ะ
- [ ] **Q3 — เฟสแรกครอบคลุมแค่ไหน?** ปัจจุบันสมมติว่าสั่ง + ส่งเข้าหน้าจอบาริสต้า
      ทางเลือกอื่นคือสั่งอย่างเดียว หรือเพิ่มการติดตามสถานะให้ลูกค้าเห็น หรือทำระบบร้านเต็มรูปแบบ
      **ผลกระทบ:** กำหนดจำนวนงานใน backlog โดยตรง
- [ ] **Q4 — จัดการเมนูที่ของหมดอย่างไร?** ปัจจุบันสมมติว่าพนักงานกดปิด/เปิดเมนูเอง
      ทางเลือกอื่นคือตัดสต๊อกอัตโนมัติตามวัตถุดิบ หรือยังไม่ทำในเฟสแรก
      **ผลกระทบ:** กระทบ BR-3, AC-2, AC-7 และ BL-001
- [ ] **Q5 — จำนวนโต๊ะในร้านมีกี่โต๊ะ และมีการจัดโซนหรือไม่?** ยังไม่ได้ถาม
      กระทบการออกแบบระบบจัดการโต๊ะและการพิมพ์ QR
- [ ] **Q6 — ต้องออกใบเสร็จหรือใบกำกับภาษีหรือไม่?** ยังไม่ได้ถาม
      หากต้องออก จะมีข้อกำหนดทางกฎหมายเพิ่มเข้ามา
      ประเด็นนี้ถูกยกไปพิจารณาต่อใน [[20260802-02-pdpa-it-compliance|20260802-02]] (คำถาม Q2)
