## 16:46 — ตัดสินใจ Table ทั่วไป (Column, Sort, Filter) ใน DESIGN.md

**สิ่งที่ทำ**

- แก้ DESIGN.md §3 (Table) — ตัดสินใจ header style, การแบ่งแถวด้วยเส้นขอบ
  (ไม่ zebra striping), คอลัมน์ตัวเลขชิดขวา + tabular-nums, hover สีอ่อน, และ
  **ตัดสินใจไม่ทำ Sort/Filter ตอนนี้** พร้อมเหตุผล
- เพิ่มแถวใน §7 Design Decisions
- แก้ mockup 2 จุดที่ไม่ตรง — คอลัมน์ราคาไม่ได้ชิดขวา (มีแค่ tabular-nums)
  และไม่มี hover state ให้แถวในตาราง — เพิ่มทั้งสองอย่าง republish ที่ URL เดิม

**เหตุผลและการตัดสินใจ**

- **Sort และ Filter ตัดสินใจว่า "ยังไม่ทำ" ไม่ใช่ "ยังไม่รู้"** — ต่างจาก Shadows
  (ที่ยังเป็น TBD จริง ๆ) นี่คือการตัดสินใจเชิงรุกว่าจะไม่สร้าง feature ที่ไม่มี
  ปัญหาจริงรองรับ: ตารางเดียวที่มีอยู่ (จัดการเมนู) เป็น list เล็กที่พนักงานสร้างเอง
  10-30 รายการ การเรียงลำดับหรือกรองข้อมูลจะไม่แก้ปัญหาอะไรจริง ๆ ในระดับนี้
- **ระบุไว้ล่วงหน้าว่าตารางที่น่าจะต้องมี filter ในอนาคตคือ "order-status review"**
  (สเปค §3 พูดถึงไว้แต่ยังไม่มีหน้าจอจริง) — เพื่อไม่ให้เข้าใจผิดว่ากฎ "ไม่ต้องมี
  filter" นี้ใช้ตลอดไปกับทุกตาราง เป็นการตัดสินใจตามสภาพปัจจุบัน ไม่ใช่หลักการถาวร
- **คอลัมน์ตัวเลขต้องชิดขวา** ไม่ใช่แค่ tabular-nums เพราะการจัดชิดซ้ายทำให้ตัวเลข
  ที่จำนวนหลักต่างกันเทียบกันยาก (เช่น ฿45 กับ ฿1,200) — พบว่า mockup มี
  tabular-nums แต่ยังไม่ได้ชิดขวาจริง จึงเป็นจุดที่ต้องแก้
- **ไม่เพิ่ม zebra striping** ให้สอดคล้องกับกฎเดียวกับ Card ที่ตัดสินไปแล้วว่าใช้
  เส้นขอบแยก ไม่ใช่แถบสี — รักษาความสม่ำเสมอของหลักการ ไม่ใช่ตัดสินใจใหม่แยกกัน
